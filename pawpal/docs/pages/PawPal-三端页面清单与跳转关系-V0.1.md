## 1. 信息架构与共用原则

主人和照护人员使用同一个微信小程序；主人默认身份，人员审核通过后可主动切换。管理后台为独立网页入口。不能因切换身份改变订单归属，不能接受自己的订单。

建议导航：

| 端 | 一级导航 | 二级内容 |
|---|---|---|
| 主人端 | 首页／订单／消息／我的 | 首页发起预约；订单管理主订单和场次；我的管理宠物、地址和身份 |
| 人员端 | 工作台／任务／消息／我的 | 工作台处理接单请求；任务安排已接服务；我的管理资料、档期和收入 |
| 后台 | 工作台／人员审核／宠物核实／订单／异常／争议／资金／规则 | 各栏目由列表进入详情，按权限显示操作 |

主订单详情聚合多日多场；场次详情负责单次上门。付款、预约、履约、报告确认、退款、打款分别展示，不能用一个“已完成”替代所有状态。场次取消成功后即使退款未到账，也不能恢复履约按钮。

清单中的“页”“弹层”“步骤”“详情子视图”是信息视图，不等于最终独立页面数量。相同主体的不同状态优先复用同一页面。下文使用 C、O、S、A 编号追踪跳转，不代表开发路由。

## 6. 主要跳转关系

### 6.1 首次预约与审核

O01 → O06 → 缺宠物到O03／缺地址到O05 → 回O06 → O07 → O08 → O09 → O10 → O11 → O13。

疑似准入问题：O03/O06 → O04；后台A05 → A06审核 → 通知C02 → O04 → 回原草稿O06并重新校验。未通过不得到付款；审核通过不代表原档期仍可用。

人员入驻：C03 → C04 → S02 → S03；后台A03 → A04 → 审核通知S03 → S04 → S05 → S01。审核通过前不开放有效接单操作。

### 6.2 接单成功、失败与重新预约

原单支付到账 → O13显示待接与截止时间，同时S06 → S07。人员接受全部场次且档期校验成功 → 主人O13显示预约成功，人员S08出现任务。

拒绝或超时 → O13显示预约失败及退款进度 → O16查看退款；主人选择重新预约 → O06复用资料 → O07另选 → O10重核价格与时间 → O11为新单支付。原退款继续独立处理，不能显示为已经抵扣新单。

到账时首场提前量：不足3小时失败全退；3至不足6小时紧急，30分钟接单期限；至少6小时普通，3小时期限。后续倒计时不重新划分紧急类型。待接不锁档，接受时全单检查，取消与接受同时发生取消优先。

### 6.3 正常履约与报告

人员S08 → S09 → S10确认实际交接／入户 → S11履约 → S12完整照片报告并标记完成 → 主人C02 → O17 → 无异常或12小时无异议 → O14确认结果。

每场重复以上流程；前一场确认窗口不阻塞下一场。预授权允许正常进入且完成确认时，不因主人未在线就归责无法交接。必要时O14展示远程确认操作，由S10接收结果。

### 6.4 取消与退款

O13选场／O14单场 → O15预览 → 主人正式提交 → 逐场返回结果 → O13/O14更新已取消 → O16追踪退款。

计算使用“预约开始时间减用户正式提交取消时间”：至少24小时全退；1至不足24小时退80%；不足1小时可取消不退款。只适用于普通可取消未开始场次。待接单撤回全退；已开始、已完成、迟到责任或无法交接争议进入O18，不能直接套用普通规则。

普通取消即时生效；人员S09收到取消状态不能再开始。批量取消部分失败时，O15保留逐场失败理由，不撤销成功项；取消不影响未选择场次。预览与提交之间条件变动需重新确认，不能沿用旧页面偷偷改变金额。

### 6.5 等待与加时

无法交接：S10 → S13记录联系／报备；如主人要求等待，S14形成请求 → O19选择等待期限并确认 → O11预付 → O19/S14同步支付结果 → S10继续等待。

等待从原预约开始时间起算，前10分钟免费，之后每10分钟档5元，最多等60分钟、最高25元；不对人员早到或其迟到收取等待费。实际交接时停止等待，实际费用100%归人员，预付未用部分退回并在O16显示。超过上限停止继续计费并报备；主人责任无法交接成立后该场原费不退、双方各50%，不再另扣普通取消费。

临时加时：S11 → S14先确认档期可容纳 → O19确认15分钟整数单位及金额 → O11付款 → S14确认到账 → S11执行新增服务。未支付不执行加项，原已付服务继续。猫狗加时均10元／15分钟，正常及加时人员85%、平台15%。

### 6.6 异常、替补与争议

主人O18或人员S13报备 → 后台A09 → A10核实 → 需要替补时提出方案 → O20主人确认 → 受影响O14/S09更新实际人员。未受影响场次保持预约状态。替补未达成时处理受影响未履约场次全退；差价和时限未定，不默认补收款。

报告异议：O17 → O18 → A11 → A12，人员S13补证；处理结论关联A14资金处理，返回O18/S13。整单暂停打款，无争议部分也不提前支付；该冻结不能自动取消其他场次。

### 6.7 整单结算与角色通知

全部场次有最终结果 ＋ 已完成场次无异议 ＋ 退款、争议及相关财务事项已处理 → 发起整单打款 → S16打款中 → 实际到账后S16已到账；失败转A13/A14处理。12小时按各场报告计时，不能只看最后一场是否确认。

C02通知 → 检查目标角色 → 必要时C04明确切换 → 目标详情。无资格访问时给出原因，不展示他人地址或收入。后台链接只能后台授权账户访问。

## 8. 关键状态与按钮约束

| 当前对象／状态 | 可见主要操作 | 必须限制 |

## 9. 低保真必须覆盖的异常与共用状态

- 所有列表：加载、无数据、无匹配、加载失败与重试；详情不存在或无权限时提供安全返回。
- 草稿：资料不全、准入待核实、档期变化、支付时跨越3小时界限；可返回修改，不能产生看似成功的无效预约。
- 付款：成功、失败、结果待核实、用户返回；重新进入依据真实订单结果，不凭前端按钮点击判断到账。
- 取消：预览变化、提交中防重复、部分成功、已开始失败、退款处理中或失败。
- 照片：上传中、失败重试、必需材料缺失；这些状态不得开始完成确认倒计时。
- 消息：通知未读和发送失败不改变业务事实；用户重进详情能看最新结果。
- 权限：角色切换、资格暂停、登录失效及敏感资料隐藏；不把未经授权的入户说明放在普通推送文本中。
